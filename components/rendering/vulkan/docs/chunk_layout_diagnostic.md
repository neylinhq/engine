# Диагностика представлений чанков

`rendering_chunk_layout_performance_test` сравнивает стоимость `shootRay`
при хранении чанков в отдельных изображениях R32 (`split`) и одном изображении
RG32 (`packed`). Это интеграционная диагностика компонента Vulkan. Она трассирует
лучи в синтетическом пустом объёме. Диагностика не генерирует сцену, не обрабатывает
очереди AADF и не выполняет полный рендер кадра. Для сценариев приложения
используется Benchmark.

## Запуск

Сборка цели и пример небольшого прогона в PowerShell из корня проекта:

```powershell
cmake --build out/release --target rendering_chunk_layout_performance_test
New-Item -ItemType Directory -Path C:\Measurements\chunk-layout
.\out\release\bin\rendering_chunk_layout_performance_test.exe --shaders out/release/components/rendering/vulkan --size 64 64 64 --rays 1025 --frames 2 --warmup 1 --layout split --validation > C:\Measurements\chunk-layout\split.csv 2> C:\Measurements\chunk-layout\split.meta
```

В Linux используется исполняемый файл без расширения `.exe`. Диагностика создаёт
скрытое окно GLFW; для её работы нужны дисплей и совместимое устройство Vulkan.
`--help` выводит параметры без запуска GPU-нагрузки.

| Параметр | Назначение |
|---|---|
| `--shaders DIR` | Каталог `trace_probe.spv`, файла отражения и варианта `packed/` |
| `--size X Y Z` | Размер в вокселях, кратный стороне чанка 16 |
| `--layout split\|packed` | Принудительный выбор представления без автоматической подмены |
| `--pattern uniform\|varied` | Однородные или меняющиеся консервативные границы пустоты |
| `--rays N` | Число лучей в повторяемом пакете |
| `--warmup N` | Число неизмеряемых запусков перед измерением |
| `--frames N` | Число измеряемых запусков трассировки |
| `--validation` | Включение слоя валидации Vulkan для проверки корректности |

Размеры ограничены диапазоном координат 32768 × 16384 × 32768 и возможностями
изображений устройства. Полезный объём хранения — восемь байт на чанк в обоих
представлениях. Например, размер 16384 × 4096 × 16384 требует 2 GiB полезных
данных изображений чанков, без очередей AADF и полной CPU-копии мира.

## Условия сравнения

`uniform` задаёт всем шести полям границ значение 31 через очистку изображения.
`varied` формирует детерминированные значения 1…31 для каждого чанка и загружает
их плитками через временный буфер до 16 MiB. Буфер освобождается до прогрева.
Все чанки пусты, слова сущностей нулевые. Входные лучи детерминированы и
не меняются между запусками одного прогона.

Сравнивайте split и packed при одинаковых размерах мира, шаблоне, лучах
и шейдерах, на одном устройстве. Чередуйте порядок запусков.
Отпечатки геометрии и лучей в метаданных должны совпадать.
Разные шаблоны меняют и работу обхода, поэтому не изолируют стоимость формата.
Прогон с `--validation` проверяет корректность; время измеряйте отдельно,
без этого флага и конкурирующей нагрузки.

## Результаты

CSV выводится в stdout, метаданные — в stderr. Сохраняйте оба файла во внешнем
каталоге измерений. Временные метки GPU охватывают dispatch трассировки и
следующий барьер. Подготовка ресурсов, загрузка входа, запись команд CPU,
ожидания отправки и чтение итогового результата не входят в этот интервал.

После измерений проверяется, что для всех лучей получен результат «нет попадания».
Ошибка даёт ненулевой код выхода; CSV записывается после успешной проверки.
Метаданные фиксируют устройство, представление, шаблон, отпечатки входа,
число прогревов и измерений, проверки данных и размеры аллокаций.

Эти времена описывают изолированную трассировку. Пустой объём, повторяющиеся
лучи и возможное сжатие изображений драйвером не воспроизводят нагрузку
произвольной сцены и не определяют FPS приложения.
