# Рендерер Vulkan

Компонент реализует рендер Albedo, Base и PathTracer, GPU-генерацию мира,
дедупликацию блоков, применение правок, обновление сущностей и обслуживание
AADF. Публичный API находится в `include/engine/rendering/vulkan/renderer.hpp`.
Типы Vulkan и ImGui скрыты в реализации.

## Устройство и ресурсы

Требуются Vulkan 1.3, общая очередь graphics/compute/present, `synchronization2`,
`dynamicRendering`, `shaderDrawParameters`, `scalarBlockLayout`, `shaderFloat16`,
`shaderInt16` и `shaderStorageImageExtendedFormats`. Формат `R32_UINT` должен
поддерживать чтение как текстуры, storage, атомарные операции и перенос данных.
Рендерер выбирает первое подходящее устройство из перечисленных Vulkan.

`Configuration::chunk_layout` задаёт представление чанков:

- `split` — два изображения `R32_UINT`: геометрия/AADF и ссылки на сущности;
- `packed` — одно изменяемое изображение `R32G32_UINT` и совместимое представление
  `R64_UINT` для атомарного доступа к той же памяти;
- `automatic` — packed при поддержке устройства, иначе split.

Packed дополнительно требует little-endian, `shaderInt64`,
`VK_EXT_shader_image_atomic_int64` с `shaderImageInt64Atomics` и совместимых
форматов изображений. Принудительный неподдерживаемый packed завершается ошибкой.
Оба варианта хранят восемь полезных байтов на чанк. Обновление AADF использует
нативные атомарные чтения и обмены с областью Device и семантикой Relaxed.

Размеры мира ограничиваются возможностями изображений и storage-буферов
устройства. Внутреннее разрешение рендера может уменьшаться с сохранением
пропорций, чтобы размеры буферов истории и число вычислительных групп
не превышали ограничений устройства. Размеры окна и UI при этом сохраняются;
фактические размеры доступны в `Statistics`.

## Мир и жизненный цикл кадра

`Renderer::generate_world(World&, ...)` строит данные на GPU и согласованно
заменяет мир на CPU и GPU. Копия для редактирования и запросов содержит данные
до построения AADF. При ошибке замены сохраняется предыдущая сцена. Перегрузка,
возвращающая `GeneratedWorld`, оставляет принятие CPU-данных вызывающей стороне.

Правки передаются компактными журналами чанков, блоков, вокселей и групп.
Неизменённая геометрия остаётся на GPU. Материалы и данные сущностей обновляются
по ревизиям. Генерация и изменения мира используют те же ресурсы, которые читает
рендер; полной загрузки мира после каждого мазка кисти нет.

Создайте `Renderer` после `Window`; окно должно существовать до уничтожения
рендерера. Кадр начинается с `begin_frame()`, возвращающего
`std::expected<bool, std::string>`. Сначала проверьте наличие ошибки, затем
значение результата. Успешный результат `false` означает, что изображение
недоступно и `draw` в этом кадре вызывать нельзя. При `true` приложение строит UI
и передаёт данные сцены через `FrameInput` в `draw`.

По умолчанию ожидание предыдущей отправки отложено до записи новых команд:
CPU может подготовить UI, камеру и правки мира. Командные ресурсы и кешированные
привязки переиспользуются только после сигнала fence. `Configuration::defer_frame_wait`
позволяет выбрать раннее ожидание для сравнительной диагностики.

`restart()` пересоздаёт выбранный рендерер при следующем `draw`, в том числе
при повторном выборе того же режима. `reset_accumulation()` запрашивает сброс
накопления. `finish()` ожидает последнюю отправку и собирает её временные метки,
не создавая нового кадра.

## Вывод и захват

При подходящем формате sRGB и поддержке цветового вложения сцена и ImGui рисуются
прямо в swapchain. Иначе используется промежуточное изображение с копированием.
`Configuration::offscreen_output` принудительно выбирает промежуточный путь.
`Statistics::direct_output` показывает выбранный путь, а после отправки —
фактический путь последнего кадра.

Перед `draw` установите `FrameInput::capture_scene` для снимка сцены до ImGui
или `capture_output` для снимка вместе с UI. После отрисовки вызовите
`screenshot(path)`. Если установлены оба флага, приоритет у сцены без UI.
Запрос захвата сохраняет промежуточное изображение даже при обычном прямом выводе.
PNG имеет размер выходного изображения.

## Метрики и диагностика

`Statistics` содержит фактическое разрешение, представление чанков, количество
выделенной памяти, временные метки GPU и интервалы работы хоста. GPU-данные
относятся к завершённой отправке `gpu_frame_count`, а не обязательно к последнему
вызову `draw`. `profile_world_updates` и `profile_render_passes` включают
дополнительные метки; по умолчанию они выключены.

`memory_statistics()` разделяет собственные аллокации рендерера и доступные
оценки куч `VK_EXT_memory_budget`. Аллокации рендерера не равны полной резидентной
VRAM процесса и не включают внутренние расходы драйвера и UI.

Интеграционные тесты проверяют генерацию, правки, границы AADF, трассировку,
синхронизацию и жизненный цикл кадра. Для регистрации GPU-тестов в CTest включите
`ENGINE_GPU_TESTS`; им нужны дисплей и `VK_LAYER_KHRONOS_validation`.
[Диагностика представлений чанков](docs/chunk_layout_diagnostic.md) изолирует
стоимость трассировки пустого объёма. Полные сценарии производительности
описываются в [Benchmark](../../../apps/benchmark/README.md).
