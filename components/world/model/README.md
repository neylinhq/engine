# world.model

Разреженное иерархическое хранилище вокселей, материалы, направленные поля
расстояний и динамические сущности. Публичный API находится
в `include/engine/world/model`. Представление данных основано на NAADF.

## Материалы и создание мира

Библиотека моделей и глобальный реестр материалов сохраняются при замене мира;
экземпляры сущностей удаляются. Контекст палитры позволяет отличить локальные
индексы импортируемой модели от уже зарегистрированных ID мира. При создании
снимка материалы уплотняются до локальных индексов файла.

В приложениях `prepare_generation` регистрирует палитру, после чего рендерер
Vulkan строит мир на GPU и передаёт его в `adopt_generated`. Копия данных на CPU
используется для запросов и редактирования; она считывается до построения AADF.
Метод `replace` предоставляет независимую CPU-реализацию для тестов
и эталонных сравнений.

## Редактирование и синхронизация

Кисти и предварительная обработка типов сущностей выполняются на CPU.
Журналы изменений содержат уникальные индексы чанков, смещения блоков
по 64 слова и смещения вокселей по 32 слова. Изменения занятости и принадлежности
сущностей также попадают в журналы. Рендерер применяет эти обновления на GPU
и восстанавливает AADF. Приложение вызывает `acknowledge_changes` только после
успешной отправки самих обновлений: в кадровом API Vulkan — после успешного
`Renderer::draw` с `FrameInput::active == true`. Неактивный кадр пропускает правки,
поэтому его отправка не даёт оснований очищать журналы. Геометрия и материалы
имеют отдельные номера ревизий.

Массовые правки используют `chunk_voxels`, `set_chunk_voxels`, `adopt_chunk_voxels`
и `fill_chunk`. Плотный чанк содержит 4096 индексов материалов; координата X
меняется быстрее остальных.
`adopt_chunk_voxels` принимает владение данными после проверки границ и палитры.
Однородный чанк хранится компактно, без плотного массива.

`at` и `chunk_voxels` учитывают ещё не зафиксированные правки. `snapshot`, `view`
и `trace` используют зафиксированную модель: после прямых правок вызывайте
`commit_edits`, прежде чем создавать снимок, передавать мир рендереру или
трассировать лучи. Операции `world.editing` фиксируют свои правки сами.
`WorldView` содержит ссылки на данные мира и не владеет ими; получайте новое
представление после изменений хранилища. `WorldView::visit_solids` принимает
конечные границы в координатах вокселей. Он синхронно передаёт обработчику
целые однородные занятые области, которые пересекают эти границы.
Обработчик возвращает `true`, чтобы завершить обход.

Независимые чанки упаковываются параллельно. Затем `commit_edits` последовательно
обновляет хеш-таблицу блоков, счётчики ссылок и журнал. Читающие потоки должны
завершить работу до того, как другой поток начнёт изменять мир.

`commit_edits(guard)` передаёт обработчику только воксели, которые станут
занятыми внутри заданных границ. Границы задаются в воксельных координатах.
Обработчик вызывается синхронно и не должен изменять мир. Если он блокирует
хотя бы один воксель или границы проверки недействительны, метод отменяет
все ожидающие правки и возвращает `false`.
