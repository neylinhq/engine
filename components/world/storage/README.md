# Файловые форматы мира

Компонент загружает воксельные модели и сетки, сохраняет миры CVox и читает
пути камеры PNB. Публичный API находится в `include/engine/world/storage/storage.hpp`.
Кодеки реализованы внутри компонента; внешние конвертеры не запускаются.

| Формат | Поддержка |
|---|---|
| CVox | Чтение версий 1–3, запись версии 3, контейнеры ZIP/ZIP64 и DEFLATE |
| MagicaVoxel VOX | Импорт моделей, палитр, материалов и графа сцены |
| VL32 | Импорт координат и цветов вокселей |
| OBJ / STL | Вокселизация сеток, материалы MTL и текстуры OBJ |
| PNB | Чтение и запись двоичного пути камеры NAADF |

`load` выбирает загрузчик по расширению. Для сеток `ImportOptions` задаёт
максимальный размер, размер палитры и перестановку осей. Текстуры PNG, JPEG,
BMP, GIF и PPM декодируются средствами компонента. Неподдерживаемые варианты
формата или повреждённые данные приводят к ошибке импорта.

Материалы загруженной модели имеют локальные ID. Их регистрацию в общем
реестре мира выполняет `world.model`; файловый загрузчик не назначает глобальные
ID. При сохранении используйте снимок мира с локальной палитрой. Прямые правки
нужно зафиксировать до создания снимка:

```cpp
world.set(position, material);
world.commit_edits();
engine::world::storage::save_cvox(path, world.snapshot());
```

Операции `world.editing` фиксируют свои правки сами.

`PathNode` хранит позицию, направление, скорость и имя. Числа в PNB записываются
в порядке little-endian. Имена узлов сохраняются в ASCII; символы вне ASCII
заменяются знаками `?`. Это ограничение имён внутри PNB, а не пути самого файла:
API принимает `std::filesystem::path`, а приложения преобразуют пользовательский
текст путей на границе CLI и UI.

Тестовые данные форматов находятся в `tests/fixtures/import`, примеры JPEG и
независимые эталоны декодирования — в `tests/fixtures/jpeg`. Эти файлы нужны
тестам и не входят в установочный пакет приложений.
